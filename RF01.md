
## RF-01: Gestión de Sesión, Presencia y Registro de Clientes

### Cómo ejecutar

```bash
# Terminal 1 — servidor (puerto TCP 10000)
gradlew :server:run

# Terminales 2, 3, ... — un cliente por terminal
gradlew :client:run --console=plain -q
# servidor en otra máquina de la LAN:
gradlew :client:run --console=plain -q --args="--Chat.Server.Host=192.168.1.10 --Callback.PublishedHost=<IP de este cliente>"
```

Comandos del cliente: `/login <nick>`, `/users`, `/logout`, `/help`, `/quit`.

### Contrato Slice (`common/src/main/slice/Session.ice`)

RF-01 tiene su propio archivo `.ice`, separado de `Chat.ice` (RF-03). Hace `#include "Chat.ice"` para reutilizar la excepción base `ChatException`. La tarea `compileSlice` compila todos los `.ice` de la carpeta.

| Elemento | Propósito |
|---|---|
| `struct UserInfo` / `UserInfoSeq` | Nickname y hora de conexión de cada usuario en línea |
| `enum DisconnectReason` | `Voluntary`, `ConnectionLost`, `Unresponsive`, `ServerShutdown` |
| `NicknameInUseException`, `InvalidNicknameException`, `InvalidCallbackException`, `NotLoggedInException` | Excepciones personalizadas (heredan de `ChatException`) |
| `interface SessionManager` (servidor, identidad `SessionManager`) | `login(nick, ClientCallback*)`, `logout(nick)`, `getOnlineUsers()` |
| `interface ClientCallback` (cliente) | `userConnected(UserInfo)`, `userDisconnected(nick, reason)`, `sessionTerminated` |

### Diseño

- **Unicidad del nickname:** `UserRegistry` usa un `ConcurrentHashMap` y `putIfAbsent`, así dos logins simultáneos con el mismo nombre nunca ganan ambos. La comparación no distingue mayúsculas (`Ana` = `ana`).
- **Callbacks:** el cliente crea el adaptador `Callback` (puerto asignado por el SO), registra su servant con una identidad UUID y **lo activa antes** del login. El servidor hace `ice_ping` al proxy antes de aceptarlo.
- **Presencia:** las notificaciones se envían con invocaciones asíncronas (`...Async`), para que un cliente lento no bloquee a los demás.
- **Tolerancia a fallos (3 niveles):**
  1. *Close callback* en la conexión del login: si el proceso cliente muere, se detecta de inmediato.
  2. *ACM* (heartbeats): si la red se cae sin cerrar el socket, la conexión se cierra tras `Session.ConnectionTimeout` s (30 por defecto).
  3. *SessionReaper*: cada `Session.ReaperPeriod` s (10 por defecto) hace `ice_ping` a cada callback; también se remueve a cualquier cliente cuyo callback falle.
- **Logout ordenado:** limpia el proxy y notifica a los demás. Solo la conexión que hizo el login puede cerrar esa sesión. Con `/quit` o Ctrl+C el cliente también hace logout.
- **Integración con otros RF:** `registry.callbackOf(nick)` devuelve el proxy de un usuario, y `registry.addListener(...)` permite limpiar salas y llamadas cuando alguien se desconecta.
